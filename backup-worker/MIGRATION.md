# 🚚 מדריך המעבר המלא: Google Sheets → Cloudflare Worker

מדריך זה מסביר **בדיוק איך** לעבור מהשרת הישן (Google Apps Script + Google Sheets)
לשרת החדש (Cloudflare Worker + KV) — בלי להפיל אף משתמש, ובלי לאבד נתונים.

> **עיקרון-העל של המעבר:** הנתונים נשארים **בשני המקומות** לאורך כל התקופה.
> השרת הישן ממשיך לעבוד כל עוד יש משתמשים שעוד לא עדכנו גרסה,
> והשרת החדש משרת את אלה שכבר עברו. שום דבר לא נמחק משום מקום.

---

## מה הולך לקרות — תמונה כוללת

| שלב | מה עושים | מי מושפע |
|---|---|---|
| **0** | הכנות (פריסת ה-Worker, איסוף כתובות, גיבוי) | אף אחד |
| **א** | בונים "עותק חדש" ובודקים אותו מכל הכיוונים (אתר + דסקטופ + נטפרי) | רק משתמשי הבדיקה |
| **ב** | מעבירים את כל הנתונים מהגיליון לשרת החדש (הגירה) | אף אחד — רק העתקה |
| **ג** | תקופת מעבר: שני השרתים חיים, מריצים סנכרון חוזר מדי פעם | משתמשים שעדכנו גרסה עוברים לחדש |
| **ד** | סיום: כשכולם עברו — אפשר לסגור את הישן | אף אחד (הכל כבר בחדש) |

- [ ] מחשב שיכול להגיע **גם** לכתובת הישנה **וגם** לחדשה.
      ⚠️ אם המחשב שלך עצמו תחת סינון נטפרי שחוסם את `script.google.com` —
      הרץ את ההגירה ממחשב אחר / מנקודה חמה של הטלפון. (ההגירה היא חד-פעמית וקצרה.)

# חלק א' — בדיקת העותק החדש (לפני המעבר)

> המטרה: לוודא שהשרת החדש עובד מקצה לקצה — **לפני** שמעבירים אליו מישהו.

## שלב 1: בדיקת החיבור לשרת החדש

1. פתח בדפדפן: `https://master-auth-backup.XXXX.workers.dev/?action=ping`
2. צפוי לחזור:
   ```json
   {"success":true,"message":"Connection successful! Backup server is alive."}
   ```
3. בדוק גם מהטרמינל (אותו דבר):
   ```bash
   curl "https://master-auth-backup.XXXX.workers.dev/?action=ping"
   ```

## שלב 2: בדיקת עגולה מלאה באתר (עם אימייל בדיקה)

**יוצרים עותק בדיקה של האתר** — לא נוגעים בקובץ הרשמי עדיין:

1. העתק את `index.html` לקובץ חדש באותה תיקייה: `index-test.html`.
2. פתח את `index-test.html` בעורך וחפש את השורה:
   ```js
   const DEVELOPER_SCRIPT_URL = "https://master-auth-backup.YOUR_WORKERS_SUBDOMAIN.workers.dev";
   ```
   החלף את `YOUR_WORKERS_SUBDOMAIN` בכתובת האמיתית.
   (אם הגדרת `API_TOKEN` בשרת — הגדר אותו גם בקבוע `DEVELOPER_API_TOKEN` שמופיע לידו.)
3. פתח את `index-test.html` בדפדפן (לחיצה כפולה — נפתח מקומית).
4. עכשיו תרחיש הבדיקה המלא, צעד-צעד:
   - [ ] במסך הכניסה בחר **"יצירת חשבון חדש"** והזן אימייל בדיקה
         (למשל `test-migration@example.com`) וסיסמה.
   - [ ] הוסף 2 חשבונות לדוגמה (תווית + קוד סודי TOTP כלשהו).
   - [ ] לחץ **סנכרון** (או צא ונכנס שוב) — אמורה להופיע הודעת "הכספת סונכרנה בהצלחה".
   - [ ] **צא** מהחשבון.
   - [ ] היכנס שוב עם אותו אימייל וסיסמה — כל החשבונות חייבים לחזור.
   - [ ] בדוק שסריקת QR עובדת (אם יש לך קוד סודי — סרוק אותו).
5. הערה: אימייל הבדיקה יישאר בשרת החדש כנתון ריק חסר משמעות.
   אפשר למחוק אותו בסוף מהדשבורד של Cloudflare (Workers → KV → עיון במפתחות) — או פשוט להשאירו.

**חלופה:** אם עדיף לבדוק דרך רשת (ולא מקומית) — פרסם את `verification-app-repo`
ל-GitHub Pages אחרי עדכון הכתובת בו, ובדוק שם.

## שלב 3: בדיקת אפליקציית הדסקטופ (אופציונלי בשלב הבדיקה)

1. עדכן את הכתובת בשורה 45 של `MasterAuthenticator/MainWindow.xaml.cs`
   (ואת ה-`DeveloperApiToken` אם הוגדר Token).
2. בנה EXE בדיקה:
   ```bash
   dotnet publish MasterAuthenticator/MasterAuthenticator.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
   ```
3. פתח את ה-EXE, היכנס עם אותו אימייל בדיקה וסיסמה — הכספת חייבת להיטען.
   (אל תפיץ את ה-EXE הזה — הוא עדיין לא לגרסה הרשמית אם לא החלפת את הכתובת בקוד הרשמי.)

## שלב 4: בדיקת נטפרי (הבדיקה החשובה ביותר)

1. בקש מחבר עם **הסינון המחמיר ביותר** שיש לך:
   - לפתוח בדפדפן את `https://master-auth-backup.XXXX.workers.dev/?action=ping`
   - להיכנס לאתר החדש (או ל-`index-test.html` ששלחת לו) עם אימייל בדיקה
   - אם אפשר — גם להריץ את ה-EXE של הדסקטופ
2. אם **חסום** אצל החבר:
   - הפתרון המיידי: החבר מוסיף את הדומיין לרשימה הלבנה **האישית** שלו (בפרופיל נטפרי) — עובד מיד.
   - הפתרון הקבוע: הגשת בקשה לנטפרי (`info@netfree.link` או `07-2277-2255`).
     השרת מחזיר רק JSON טקסטואלי — הסיווג צפוי להיות "גישה מלאה" ומהיר.

## שלב 5: רשימת GO/NO-GO

רק אם **כל** אלה תקינים — ממשיכים לחלק ב':

- [ ] `ping` עובד בדפדפן ובטרמינל
- [ ] מחזור הצפנה מלא עובד באתר (יצירה → סנכרון → יציאה → כניסה)
- [ ] סריקת QR עובדת
- [ ] הדסקטופ נכנס וטוען כספת (אם נבדק)
- [ ] החבר עם הסינון המחמיר נכנס בהצלחה (או שהדומיין הוסף ללבנים)
- [ ] גיבוי הגיליון בוצע (ראו שלב 6 — חובה לפני הכל!)

# חלק ב' — העברת הנתונים (הגירה)

## שלב 6: גיבוי הגיליון (חובה! לא לדלג)

1. פתח את הגיליון ב-Google Sheets.
2. **File → Make a copy** — צור עותק פרטי בשם "Credentials-BACKUP-תאריך".
3. בנוסף: **File → Download → Microsoft Excel (.xlsx)** ושמור במחשב.
4. סמן ☑ שאתה יודע שהעותק נפתח ונראה תקין (יש בו את כל השורות).

## שלב 7: הוספת פעולת הייצוא לסקריפט הישן

הסקריפט הישן לא יודע לייצא את כל המשתמשים — נוסיף לו פעולה אחת
(הוספה בלבד, לא משנה שום התנהגות קיימת — הלקוחות הישנים לא מושפעים):

1. פתח את הפרויקט ב-https://script.google.com (עורך ה-Apps Script).
2. **אל תמחק שום דבר קיים** — רק הוסף את שלושת החלקים הבאים:

**א. קבוע מפתח הייצוא** — הוסף בראש הקובץ, ליד הקבועים הקיימים:
```js
// [הגירה בלבד] מפתח גישה לפעולת export_all - החלף במחרוזת אקראית ארוכה!
const EXPORT_KEY = "החלף-למחרוזת-אקראית-ארוכה-כמו-xyz-123-אבג-456";
```

**ב. ענף הפעולה** — בתוך הפונקציה `handleRequest`, ממש לפני השורה של `action === "ping"`:
```js
    } else if (action === "export_all") {
      // [הגירה בלבד] ייצוא כל השורות לשרת החדש (Cloudflare Worker).
      if (EXPORT_KEY && params.export_key !== EXPORT_KEY) {
        return jsonResponse({ success: false, message: "Unauthorized" }, headers);
      }
      const result = exportAllFromSheet(sheet);
      return jsonResponse(result, headers);
```

**ג. הפונקציה** — הוסף בסוף הקובץ:
```js
function exportAllFromSheet(sheet) {
  const data = sheet.getDataRange().getValues();
  const users = [];
  for (let i = 1; i < data.length; i++) {
    const email = (data[i][COLUMN_EMAIL - 1] || "").toString().trim().toLowerCase();
    if (!email) continue; // שורת כותרת או שורות ריקות
    users.push({
      email: email,
      password: (data[i][COLUMN_PASSWORD - 1] || "").toString().trim(),
      vault: (data[i][COLUMN_VAULT - 1] || "").toString().trim(),
      updatedAt: (data[i][COLUMN_TIMESTAMP - 1] || "").toString().trim()
    });
  }
  const tz = Session.getScriptTimeZone();
  const tzOffset = Utilities.formatDate(new Date(), tz, "Z"); // למשל "+0300"
  return { success: true, count: users.length, tzOffset: tzOffset, users: users };
}
```

> הקוד הזה כבר קיים גם בקובץ `apps_script.js` בפרויקט שלך — אבל **חשוב להדביק ידנית
> רק את שלושת החלקים** לתוך הסקריפט הפרוס (אל תדרוס את כל הקובץ —
> ייתכן שהגרסה הפרוסה שונה מהקובץ שבתיקייה).

3. לחץ **💾 Save** (או Ctrl+S).
4. פריסה מחדש כך שהשינוי ייכנס לפעולה:
   - **Deploy → Manage deployments**
   - ליד הפריסה הקיימת (Web app) לחץ על **עיפרון (Edit)** ✏️
   - ב-**Version** בחר **New version** → לחץ **Deploy**
   - **חשוב:** זה מעדכן את אותה כתובת — הלקוחות הישנים ממשיכים לעבוד כמו קודם.
5. בדיקת שפיות מהירה: פתח בדפדפן
   `<הכתובת-הישנה>?action=ping` — חייב להחזיר "Connection successful".

## שלב 8: בדיקת הייצוא

1. פתח בדפדפן (שימו לב ל-`export_key`):
   ```
   https://script.google.com/macros/s/המזהה-שלך/exec?action=export_all&export_key=המחרוזת-שבחרת
   ```
2. צפויה תשובה JSON מהצורה:
   ```json
   {"success":true,"count":12,"tzOffset":"+0300","users":[{"email":"...","password":"...","vault":"{...}","updatedAt":"..."}, ...]}
   ```
3. ⚠️ **אזהרה:** התשובה מכילה את כל האסימונים המוצפנים של כל המשתמשים.
   אל תשתף את הקישור הזה עם אף אחד. (הנתונים מוצפנים — אבל אל תתפרסם אותם סתם.)
4. אם קיבלת `Unauthorized` — ה-`export_key` לא נכון. אם קיבלת דף ריק/שגיאה —
   החזרה לשלב 7 ובדוק שהדבקת נכון ופרסת גרסה חדשה.

## שלב 9: הרצת ההגירה

פתח טרמינל בתיקיית הפרויקט והרץ:

**א. ריצת ניסיון (dry-run) — לא כותבת כלום:**
```bash
node backup-worker/migrate-from-sheets.mjs \
  --from "https://script.google.com/macros/s/המזהה-שלך/exec" \
  --to "https://master-auth-backup.XXXX.workers.dev" \
  --token "ה-API_TOKEN-שלך-אם-הגדרת" \
  --export-key "המחרוזת-שבחרת" \
  --dry-run
```

קרא את הדוח. הוא צריך להראות, למשל:
```
   סך הכל שורות בגיליון:      12
   שורות תקינות (עם כספת):    11
   יועברו לשרת החדש:          11
   כבר מעודכנים (נדלגו):       0
   ללא כספת (לא רלוונטי):      1
   פגומות / לא תקינות (דולגו): 0
   שגיאות:                     0
```
- שורות **"ללא כספת"** — משתמשים שנרשמו אך לא סיימו הגדרה. אין מה להעביר. תקין.
- שורות **"פגומות"** — נדלגות בכוונה (לא מעבירים אשפה לשרת החדש). אם יש כאלה —
  רשום לעצמך את המיילים ובדוק אותם בנפרד אחר כך.

**ב. הגירה מלאה** — אותה פקודה בלי `--dry-run`:
```bash
node backup-worker/migrate-from-sheets.mjs \
  --from "https://script.google.com/macros/s/המזהה-שלך/exec" \
  --to "https://master-auth-backup.XXXX.workers.dev" \
  --token "ה-API_TOKEN-שלך-אם-הגדרת" \
  --export-key "המחרוזת-שבחרת"
```

**ג. הרצה חוזרת מיד** — אותה פקודה שוב. הפעם כל השורות אמורות להופיע
כ"כבר מעודכן (נדלג)" — הוכחה שהסינכרון בטוח לחזרה.

**ד. (אופציונלי) בדיקת משתמש בודד** — אם רוצה לוודא משתמש מסוים:
```bash
node backup-worker/migrate-from-sheets.mjs \
  --from "..." --to "..." --token "..." --export-key "..." \
  --email "האימייל-של-המשתמש"
```

# חלק ג' — תקופת המעבר (נתונים בשני המקומות)

## מי כותב לאן

| מי המשתמש | לאן הכספת נשמרת | מה קורה בכניסה |
|---|---|---|
| עוד בגרסה הישנה (לא עדכן) | הגיליון הישן (כמו תמיד) | נטען מהגיליון הישן — הכל כרגיל |
| עדכן לגרסה החדשה | השרת החדש (Cloudflare) | נטען מהשרת החדש |

הנתונים קיימים בשני המקומות במקביל. **שום דבר לא נמחק מהגיליון הישן** —
הוא נשאר שלם כל עוד לא תסגור אותו (ולא תסגור אותו עד שלב ד').

## למה הרצה חוזרת בטוחה (סינכרון)

סקריפט ההגירה משווה חותמות זמן: לכל משתמש הוא בודק אם בשרת החדש יש
נתון **חדש יותר** מזה שבגיליון — ואם כן, הוא **מדלג** ולא דורס.
המשמעות:
- משתמש שעבר לגרסה החדשה ושמר כספת מעודכנת בשרת החדש → ההגירה לא תדרוס אותה.
- משתמש שעוד בגרסה הישנה ועדכן בגיליון → ההגירה תעביר את העדכון שלו לחדש.
- הרצה חוזרת אחרי הגירה מלאה מראה "הכל מעודכן" — זה תקין וזו ההוכחה שהכל מסונכרן.

## מתי להריץ סינכרון חוזר

הרץ את אותה פקודת הגירה (בלי `--dry-run`) בכל פעם ש:
- נשאר שבוע מאז ההגירה האחרונה, או
- לפני שמתחילים לעודד את הגל האחרון של המשתמשים לעדכן גרסה.

**הרץ אותה תמיד אחרי הגירה מלאה גם אם "לא קרה כלום"** — היא לא יקרה לך.

## הודעה למשתמשים (נוסח מוכן)

> שלום,
> שיפרנו את שרת הגיבוי של Master Authenticator ועברנו לשרת חדש ומהיר יותר.
> כדי להמשיך להשתמש באפליקציה יש לעדכן לגרסה החדשה.
> **אין צורך לעשות שום דבר עם הנתונים — הכל כבר הועבר אוטומטית.**
> מי שלא יעדכן ימשיך לעבוד כרגיל על השרת הישן (לעת עתה).
> בתודה, צוות Master Authenticator

## מה לא לעשות בתקופת המעבר

- ❌ אל תריץ את ההגירה עם `--force` — זה דורס נתונים חדשים יותר בשרת החדש.
- ❌ אל תסגור את הסקריפט הישן כל עוד יש משתמשים שעוד לא עדכנו.
- ❌ אל תמחק את הגיליון.
- ❌ אל תשנה את הגיליון ידנית (עמודות/כותרות) — הסקריפט הישן מצפה למבנה קבוע.

# חלק ד' — סיום המעבר

## מתי אפשר לסיים

כשמתקיים אחד מאלה:
- כל המשתמשים עדכנו גרסה (אתה יודע מי עשה מה), או
- החלטת שמי שלא עדכן עד תאריך X — יקבל הסבר והוראות עדכון, או
- עבר זמן סביר (למשל חודש) וכולם כבר על הגרסה החדשה.

## סגירת הסקריפט הישן (אופציונלי — רק כשכולם עברו)

1. בצע **הגירה אחרונה** (סינכרון סופי) — אותה פקודה.
2. בגוגל: **Deploy → Manage deployments → Edit → Disable deployment**.
   (אפשר להפעיל בחזרה בכל רגע — כלום לא נמחק.)
3. **השאר את הגיליון במנוחה** (אל תמחק) — זה העותק ההיסטורי שלך.

## ניקיון אחרון

- (אופציונלי) מחק את אימייל הבדיקה מה-KV:
  Cloudflare → Workers & Pages → KV → `VAULT_KV` → View → מחק את המפתח של אימייל הבדיקה.
- מחק את `index-test.html` שיצרת לבדיקה (או השאר אותו — הוא לא מזיק).

# פתרון בעיות

| סימפטום | סיבה סבירה | פתרון |
|---|---|---|
| ההגירה נכשלת עם "נכשל בחיבור לשרת הישן" | הכתובת שגויה / פעולת export_all לא נוספה / לא פרסת גרסה חדשה / EXPORT_KEY שגוי | חזור לשלבים 7–8; בדוק את `?action=export_all` בדפדפן; ודא שה-`--export-key` תואם |
| "Unauthorized" מהישן | ה-`export_key` שגוי | העבר את המחרוזת המדויקת שהגדרת ב-`EXPORT_KEY` |
| שגיאת `401` מה-Worker | ה-`--token` שגוי או חסר | ודא שהוא זהה ל-`API_TOKEN` שבשרת |
| בדוח מופיעות שורות "פגומות" | בגיליון יש שורות ישנות עם כספת לא-תקינה | נורמלי — הן נדלגו בכוונה. רשום את המיילים ובדוק אותם ידנית |
| בדוח מופיעות שורות "ללא כספת" | משתמשים שנרשמו אך לא סיימו הגדרה | נורמלי — אין מה להעביר |
| משתמש עבר לגרסה חדשה אבל הכספת ריקה | לא הורצה הגירה (או הורצה לפני שמירתו בגיליון) | הרץ הגירה ואז כניסה מחדש |
| ההגירה נתקעת/איטית | חיבור רשת ל-script.google.com חסום מהמחשב שלך | הרץ ממחשב ללא סינון או מנקודה חמה (שלב 0) |
| אחרי הגירה חוזרת — משתמש "נדלג" למרות שעדכן בגיליון | פער שעון בין הגיליון לשרת (עד שעה, בהחלפת שעון חורף/קיץ) | המתן קצת והרץ שוב; אם חוזר — הרץ עם `--email` של אותו משתמש בלבד |
| שכחת את ה-EXPORT_KEY | — | הגדר מפתח חדש בסקריפט, פרס גרסה חדשה, והשתמש בו |

# נספח — כל הפקודות במקום אחד

**בדיקת השרת החדש:**
```bash
curl "https://master-auth-backup.XXXX.workers.dev/?action=ping"
```

**הגירה (dry-run):**
```bash
node backup-worker/migrate-from-sheets.mjs --from "OLD_URL" --to "NEW_URL" --token "T" --export-key "K" --dry-run
```

**הגירה מלאה / סינכרון חוזר (אותה פקודה, בלי --dry-run):**
```bash
node backup-worker/migrate-from-sheets.mjs --from "OLD_URL" --to "NEW_URL" --token "T" --export-key "K"
```

**משתמש בודד:**
```bash
node backup-worker/migrate-from-sheets.mjs --from "OLD_URL" --to "NEW_URL" --token "T" --export-key "K" --email "user@example.com"
```

**בניית EXE חדש (אחרי עדכון הכתובת בקוד):**
```bash
dotnet publish MasterAuthenticator/MasterAuthenticator.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

**בדיקות הפרויקט (כולל בדיקות ההגירה):**
```bash
node backup-worker/migrate-test.mjs        # בדיקות הגירה
node backup-worker/test-worker.mjs         # יחידות
node backup-worker/integration-test.mjs    # אינטגרציה (wire)
node backup-worker/e2e-crypto-test.mjs     # קריפטוגרפיה E2E
node backup-worker/cross-csharp-test.mjs   # אינטרופ C# (דורש dotnet)
```
